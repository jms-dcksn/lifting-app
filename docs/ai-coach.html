Exception eligibility — implemented foundation (#210)

The policy takes a current, authorized history snapshot and returns typed candidates. It runs no model, sends no notification and changes no workout. The inbox and conversation journey come later. The engine still owns every number.

1. Keep context exact

Match slot, exercise, equipment instance, phase, adaptation and prescription. Reject recovery, stale or incomplete evidence.

2. Require a meaningful signal

Two first-set effort misses; two independently reduced rep-floor targets; confirmed plateau; or four-exposure decline. Significant pain stays session-level.

3. Return one candidate per slot

Group overlapping lift signals with source session/set IDs and evidence dates. Every action is recommended; none is asserted to be applied.

The path of one question

You tap the speech-bubble button with two four-point sparkles (or open /coach). The browser sends your words to a server route. That route proves you are signed in, writes your message to Postgres, asks LangChain to think, and streams the reply back. LangChain may call a tool. Each tool is a thin wrapper around an existing loader. LangSmith records the trace so you can see which tools ran.

The bubble signals conversation; the sparkles identify AI assistance. The icon inherits the button color, and the button keeps its accessible name, Coach.

Why a composite key

agent_message
(thread_id, user_id)
→
agent_thread
(id, user_id)

RLS checks a row's own user_id. It cannot see whose thread thread_id names. The composite foreign key makes Postgres reject a message aimed at another user's thread.

Recovery targets match recovery effort

The nextWorkout tool and active session share the same target engine. At four or more reps in reserve, it recalculates load from recent performance instead of adding a rep or weight. It keeps the prior reps inside the programmed range, rounds to an achievable load, and caps it at the prior load. Phase names do not control this rule; both Deload and Recovery prescriptions work.

1. Recent performance

150 lb × 7 at 1 RIR

2. Load model

Estimate strength, then solve for 7 reps at 4 RIR.

3. Shared target

135 lb × 7 at 4 RIR

Bodyweight work converts total load back to added or assisted load. Unknown bodyweight means no recovery load suggestion. Missing historical RIR uses two. Below four target RIR, normal progression stays unchanged. The agent narrates the returned numbers; it does not calculate a separate deload percentage.

src/lib/agent/thread.ts — the id rule

async function openThread(supabase: Client, userId: string, text: string) {
  const id = parseThreadId(uuid7());
  if (!id) throw new Error("Unable to create agent thread");
  const title = threadTitleFromUserText(text);
  const created = await supabase.from("agent_thread").insert({ id, user_id: userId, title });
  if (created.error) throw new Error(created.error.message);
  try {
    const userMessage = await saveMessage(supabase, userId, id, userText(text));
    return { thread: { id, title, updatedAt: userMessage.createdAt }, userMessage };
  } catch (error) {
    await supabase.from("agent_thread").delete().eq("id", id).eq("user_id", userId);
    throw error;
  }
}

The thread row exists only once you send. If the first message cannot be saved, the row is deleted again before the error reaches you.

src/lib/agent/chat-state.ts — the title rule

export function threadTitleFromUserText(text: string): string {
  const collapsed = text.replace(/\s+/g, " ").trim();
  // Code points, not UTF-16 units, so an emoji at the cut never leaves a lone surrogate.
  return Array.from(collapsed).slice(0, TITLE_LIMIT).join("") || "New chat";
}

TITLE_LIMIT is 80. The migration backfilled older threads with the same rule in SQL.

src/lib/agent/chat-handler.ts — the body must name its thread

function parseTurnRequest(body: unknown): TurnRequest | null {
  if (!body || typeof body !== "object" || !("threadId" in body)) return null;
  const { text, threadId } = body as { text?: unknown; threadId: unknown };
  const trimmed = typeof text === "string" ? text.trim() : "";
  if (!trimmed) return null;
  if (threadId === null) return { kind: "new", text: trimmed };
  const id = parseThreadId(threadId);
  return id ? { kind: "continue", threadId: id, text: trimmed } : null;
}

src/lib/agent/markdown.ts — one source, then the body

const SOURCE_LINE = /^(?:\*\*)?Source:\s*(.+?)(?:\*\*)?\s*$/i;

export function splitCoachReply(text: string): { body: string; sources: string[] } {
  const sources: string[] = [];
  const kept: string[] = [];
  for (const line of text.split("\n")) {
    const match = line.trim().match(SOURCE_LINE);
    if (!match) {
      kept.push(line);
      continue;
    }
    const source = match[1].replace(/\*\*/g, "").trim();
    if (source) sources.push(source);
  }
  return { body: kept.join("\n").replace(/\n{3,}/g, "\n\n").trim(), sources };
}

Turn activity — immediate dots, real tool progress (#203)

Send immediately creates one Coach bubble in the sheet and full-screen chat. Three dots remain through initial latency, tool execution, pauses, and streamed text. The reply grows inside the same bubble. Progress explains observed execution; it does not display or invent the model's reasoning.

1. Send

The reducer creates an in-flight turn before the server responds. The bubble already has three dots.

2. Execute tools

LangChain's execution channel supplies call IDs, tool names and completion or failure. Overlapping calls stay separate.

3. Stream answer

Text and progress share one Coach bubble. Dots remain until the turn ends, including pauses after a tool finishes.

4. End the turn

Done shows saved messages. An error or dropped connection clears activity and unlocks another send.

A completed tool means its invocation returned, not that a workout started or a program was activated. Navigation tools prepare links. Missing intake still needs an answer from the agent. The server sends no raw arguments, results, exception details, or private reasoning as progress.

      } else if (data.event === "tool-finished" || data.event === "tool-error") {
        emit({
          type: "tool-end",
          callId: data.tool_call_id,
          outcome: data.event === "tool-error" ? "error" : "complete",
        });
      }
    }

The parallel native tool projection is drained with rejection handlers: LangChain creates output promises even when this execution channel supplies the UI events. This avoids unhandled tool-output rejections.

Recent comparisons and historical trends are separate

One eligible point is not a trend. Two older points can describe a dated historical trend even when the 21-day window has a gap. Latest workout can be a deload while latestEligibleE1rm belongs to earlier normal work. Stored deload values are excluded from comparisons, not unrecorded. Window delta is last minus first eligible point.

- exerciseReview: availability.recentComparison and availability.historicalTrend are separate. export function classifyProgramIntake(input: unknown): IntakeClassification {
  const partial = partialProgramIntakeSchema.safeParse(input).data ?? {};
  const classification = { days: fieldScore(partial.days), goal: fieldScore(partial.goal), ... };
  const ready = REQUIRED_FIELDS.every((key) => classification[key].value != null)
    && classification.overallConfidence >= CONFIDENCE_THRESHOLD;
  if (!ready) return { ...classification, followUp, chips };
  return { ...classification, ready: true, intake };
}

How Coach explains a template recommendation

Before intake, Coach says it can choose an existing gallery program for review in the builder. It explains the choice using only the returned match traits. Intake confidence measures supplied fields; it does not prove the program satisfies every preference. A requested back emphasis without a matching trait is flagged for builder review.

src/lib/agent/prompt.ts — evidence for the match

When draftProgramFromIntake returns a draft, name the gallery template and explain why it matched using only matchTraits. Intake fields and classification scores describe the request, not proof that the template satisfies it.

Coach does not claim extra volume, equipment compatibility, honored omissions, or exercise substitutions without explicit tool evidence. The program is saved before Open in builder is tapped. Coach reads isActive to report its status: existing accounts receive an inactive draft; an account with no programs gets its first program activated immediately.

What Slice 0–2 will not do

  • Replace an existing active program until you save in the builder. An account with no programs activates its first program on generation.
  • Emit programs as free-form LLM JSON.
  • Accept Coach proposals or change settings (Slice 4).
  • Start a workout without the in-chat confirm chip.
  • Show the agent entry during an active session (hideAppChrome).
  • Read period observations.
  • Replace Track Coach at /analytics/coach.
  • Summarize, compact, or embed the conversation.

Recovery workouts remain training activity. Saved deload flags exclude their sets from strength trends, rep improvements, PRs and next-workout references.
